# 🔄 协议反馈学习

## 功能描述
对比用户修正前后的文本差异，提取有价值的纠错规则并更新 @translation-protocol.md 的高级规则部分。

## 执行任务

### 步骤1：差异对比
1. 读取 @TFT_processed.md 中的"B. 规范化攻略文本"（AI初次处理版本）
2. 读取 @TFT.md（用户手动修正后的版本）
3. 逐行对比，识别所有用户修正的地方

### 步骤2：筛选有价值的纠错
**只提取符合以下条件之一的纠错**：

#### 条件A：多次出现的重复错误（频率 ≥ 2）
- 统计同一错误在文本中出现的次数
- 如果某个误识别在文本中出现2次及以上，记录该纠错模式

**示例**：
- "卡萨订" → "卡萨丁" 出现3次 ✅ 记录
- "羊刀" → "鬼索的狂暴之刃" 出现1次 ❌ 不记录

#### 条件B：明显影响理解的重要错误
即使只出现1次，但属于以下类型的需要记录：
- **数字/排名严重错误**：如"120到三加" → "2到3家"
- **核心术语误判**：如将英雄名错认为羁绊名
- **语义反转错误**：如"削弱了" ↔ "还没削弱"
- **复合术语识别错误**：如"625层"被拆成"6 + 25层"
- **地区简称误判**：如"皮成" → "皮城"但被误判为其他术语

### 步骤3：分类错误类型
将提取的纠错按照以下类型分类：

| 错误类型 | 说明 | 示例 |
|---------|------|------|
| 读音误识别 | 拼音相似导致的错误 | "韦恩" → "薇恩" |
| 数字连读 | 数字组合识别错误 | "六25" → "625" |
| 复合术语 | "X比尔"、"X转"等模式 | "三比尔" → "3个比尔吉沃特单位" |
| 地区简称 | 地区名简化识别 | "皮成" → "皮城" |
| 强化符文 | 符文名称误判 | 待人工确认的符文 |
| 俚语保留 | 应保留但被转换的俚语 | "吃分"不应转为"获得积分" |
| 语义判断 | 需要上下文理解的错误 | "产了" → "削弱了"或"还没削弱" |

### 步骤4：生成规则描述
为每个有价值的纠错生成规则描述，包括：
- **规则标题**（如"某某术语识别规则"）
- **错误模式**（原文是什么样的）
- **正确模式**（应该是什么样的）
- **判断方法**（如何识别这种错误）
- **实际示例**（用户的实际修正案例）

### 步骤5：更新协议文档
1. 在 @translation-protocol.md 的"【高级规则】"部分添加新规则
2. 规则按照现有格式编写：
   - 使用三级标题（###）
   - 包含错误模式、正确模式、判断方法
   - 提供实际示例
3. 更新协议版本号和更新日期
4. 在更新内容中说明新增的规则数量

## 筛选逻辑伪代码

```python
corrections = []

# 对比差异
for each_diff in compare(TFT_processed.md, TFT.md):
    original_text = diff.before
    corrected_text = diff.after

    # 统计该错误在文本中的出现频率
    frequency = count_occurrences(original_text, TFT_processed.md)

    # 判断是否是明显错误
    is_critical = check_critical_error(original_text, corrected_text)

    # 筛选条件
    if frequency >= 2 or is_critical:
        corrections.append({
            'original': original_text,
            'corrected': corrected_text,
            'frequency': frequency,
            'type': classify_error_type(original_text, corrected_text),
            'context': extract_context(diff)
        })

# 按频率和重要性排序
corrections.sort(key=lambda x: (x['frequency'], x['is_critical']))

# 生成规则并更新协议
for correction in corrections:
    rule = generate_rule(correction)
    append_to_protocol(rule)
```

## 注意事项

1. **去重检查**：添加规则前，检查是否与现有高级规则重复
2. **规则编号**：自动为新规则分配编号（接续现有的1-8）
3. **版本更新**：自动递增版本号（如 v2.1 → v2.2）
4. **备份**：修改前自动备份 translation-protocol.md
5. **审核机制**：生成规则预览后，必须等待用户确认才执行更新
